## Verdict

Strong alpha engine, pre-beta product. LearningCore, save/sync, profile isolation and the 123 unit + 118 browser tests are solid. The product layer (monolithic `app.js`, placeholder UI, unenforced parent controls) and the release process (gitignored evidence, dirty-tree certification, ungated Pages deploy) are what block a beta. The deployed app currently has no gameplay because production mode fails closed on every content record.

## Top 10 findings (verified)

1. Production mode disables the whole game — every record is `runtime: { prototype: true, production: false }` (`content-review-manifest.js` 2855); any non-localhost host is production (`content-control-gate.js` 114–120).
2. Struggling kids get locked out permanently — `updateSkill` (`app.js` 930–950) writes `learner.contentQuarantine` after 4 attempts / 3 wrong; nothing clears it.
3. Parent PIN is plaintext, default `1234`, no attempt limit, and included in exports, cloud snapshot and the Firestore `progress` map (`app.js` 77, 873, 1739, 754).
4. Backups and recovery are no-ops — identical payload to primary/backup/recovery (`app.js` 434–440); `restoreFromRecoverySnapshot` never finds a snapshot (`brainbite-core.mjs` 2109–2122, 2384); one corrupt skill wipes all learners (core 1424–1434, 2352–2364).
5. Parent time limits are display-only (`app.js` 1204–1207 vs `launchMission` 1654).
6. Sync can loop forever — five REST calls recurse on 401 after `refresh()` returns `null` (`app.js` 722, 757, 764, 777, 784, 796).
7. Deploy is ungated — `pages.yml` deploys from `main` and `batch-9-webgl-spike`, no `needs:` on CI, rsyncs the whole repo.
8. Release evidence is not reproducible — `release-evidence/` gitignored; certification on `workingTreeClean: false`; "24/24 PASS" counts 20 perf-budget violations as passed; last local Playwright run is red.
9. 3D tap-to-answer is dead code — `.webgl-canvas { pointer-events: none }` (`styles.css` 686) vs raycaster (`webgl-battle.mjs` 302–325).
10. Snap-to-Game produces no game; Profiles / Recovery / Import / Delete are reachable without a PIN (`app.js` 1738, 1749, 1752, 1801, 1899).

## Recommended UI changes

1. One-screen battle at `100dvh`: single top bar, stage fills, boss/toast as overlays. No scroll at 390×844.
2. Kid hub = six large tiles + three icon buttons (reference structure); everything else behind Parents PIN.
3. One dock, not two; max five 56 px targets, no wrap.
4. Parent center as its own plain app shell (Progress, Limits, Profiles, Account & Sync, Data & Recovery, Advanced).
5. Landscape prompt for battle on phones.
6. One answer surface — tappable 3D pillars *or* DOM pillars, never both visible.
7. Prompt, boss name and world must come from one mission record.
8. Replace `alert()`/`confirm()` with themed focus-trapping modals.
9. Bind the minimap to real mission nodes or remove it.
10. Remove every placeholder (energy "+", "Double BrainBites Weekend", badge "3", "Friends", static XP).
11. Hide presentation badge / scene selector from children.
12. First-run choreography: name → world → guided mission with three disappearing prompts.
13. Label `#parentPinInput`, `#newProfile`, `#snapFile`, `#ocrText`; `alt` on `#snapPreview`; `aria-current`; `lang="es"` on Spanish; announce fallback via live region.
14. Self-host Fredoka/Nunito; add CSP.
15. PLAY button to CSS with `:focus-visible`, 56 px target.
16. Viewport-fit phone home (≤ 1.2× viewport height), mascot + PLAY above the fold.
17. Retire MATCH JPEG overlay once DOM layout matches reference structure; budget hand-authored textures for four assets before any new world.
